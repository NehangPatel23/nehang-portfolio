Dirscope

A native macOS app and Quick Look extension that replaces Finder's plain folder icon with a rich, interactive browser — sortable file lists, expandable subfolders, zip archive browsing, and side-panel previews, all inside the standard Quick Look panel.

Dirscope is a feature-complete dual-target Swift project: a SwiftUI host app for onboarding and settings, and an AppKit Quick Look extension embedded in Finder. Shared code handles directory listing, in-process zip parsing, cross-process preference sync, and staged archive opens — without requiring the host app window to stay open.

Context

Background & origin

Finder's built-in Quick Look preview for folders stops at a plain folder icon. Zip files fare no better — you see an archive icon, not what's inside. Opening either means a new window or extracting files to disk.

Dirscope replaces that with a full browser inside the standard Quick Look panel: list or icon view, expandable folder trees, zip contents with per-entry metadata, and a side panel for inline file previews — all triggered by pressing Space or ⌘Y on any folder or .zip in Finder.

The best system utility disappears into the workflow you already have. Quick Look is the front door — Dirscope makes it useful.

Problem

The challenge

Quick Look extensions run in a strict sandbox. They cannot spawn external tools reliably, cannot open files in other apps directly, and cannot share preferences with a host app via App Groups without a paid signing identity.

Zip browsing adds another layer: listing, nested folders, deflate extraction, side-panel previews, and opening a single file inside an archive — all without extracting the whole zip or launching the full host app UI.

Strategy

Goals & constraints

  • Replace Finder's plain folder Quick Look with a sortable, expandable file browser
  • Browse .zip archives in Quick Look without full extraction — including nested folders and nested zips
  • Preview files inside folders and archives in a side panel (text, images, Markdown, HTML, SVG)
  • Sync settings between host app and extension without App Group entitlements
  • Open individual archive entries in their default app via a sandbox-safe staging bridge
  • Ship an install script that builds, codesigns, and reloads Quick Look in one command

System

Architecture overview

The project splits into two Xcode targets sharing code from a Shared/ folder. The host app (SwiftUI) handles onboarding and settings; the Quick Look extension (AppKit) owns all preview UI and runs independently — browsing and side-panel previews work even when Dirscope's window is closed.

Preferences persist to a plist inside the extension's sandbox container. The host app writes to the same path explicitly. Changes propagate live via Darwin notifications, so settings apply without relaunching Quick Look.

Delivery

What I built

End-to-end native macOS product — from Quick Look lifecycle and sandbox constraints to install automation and cross-process coordination.

Quick Look folder browser

List and icon views with sortable columns, expandable subfolders (1–7 levels), path breadcrumb, and view switcher.

Zip archive browsing

In-process central-directory parsing for store and deflate entries; nested folders and nested zips via disclosure arrows; single-root wrapper folders stripped automatically.

Side-panel file preview

Inline preview for text, Markdown, HTML, SVG, and images — including files inside zip archives extracted on a background thread.

Cross-process settings sync

SharedPreferencesStore writes to extension container plist; Darwin notify + NotificationCenter for live updates without App Groups.

Archive entry open bridge

Extension stages one file, writes PendingOpen.plist, wakes LaunchAgent helper to open via Launch Services — no full app UI required.

Host app & install script

Dashboard, extension setup guide, Appearance/Behaviors settings; install-app.sh builds, installs to /Applications, and reloads Quick Look.

Technical

Deep dives

Sandbox-safe zip I/O

ArchiveSandboxAccess uses NSFileCoordinator reads and temp copies in the extension container. ZipArchiveReader parses central directory in-process — no unzip spawn inside the sandbox.

Opening files inside archives

The sandboxed extension cannot call NSWorkspace.open on staged files. ArchiveEntryOpenBridge writes a pending request; a user LaunchAgent runs Dirscope -backgroundOpenHelper at login to receive Darwin notifications and open staged files.

Live settings without relaunch

PreviewViewController observes both NotificationCenter and Darwin notify events. Preference writes skip unchanged values; migrations run only in the host app to avoid extension reload feedback loops.

Engineering

Hard problems

Sandbox blocks archive tools

Extension cannot spawn unzip or tar reliably.

Solution → In-process ZipArchiveReader with NSFileCoordinator; external tools as host-app fallbacks only.

Opening archive entries

Sandboxed QL extension cannot launch external apps.

Solution → ArchiveEntryOpenBridge + LaunchAgent background helper for staged opens.

Settings sync without App Groups

Ad-hoc builds lack paid signing for shared containers.

Solution → Explicit shared plist path in extension container + Darwin notifications.

Quick Look appearance drift

Inspect pane and footer retained one-time tint on theme switch.

Solution → PreviewTheme.applySurfaceBackground + viewDidChangeEffectiveAppearance refresh.

Reflection

Lessons learned

01Quick Look extensions are full apps in a tiny sandbox — design for extension-only workflows from day one.
02Cross-process prefs don't need App Groups if you know the container path and use Darwin notify.
03Archive UX in a sandbox rewards in-process parsers over shelling out to CLI tools.
